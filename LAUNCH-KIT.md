no participant data. Track every external action in [`LISTINGS.md`](LISTINGS.md).

The €50 Reservation Payment is transferred at signup and is part of the participant's total. The
remaining accommodation and food share is paid later in cash at the venue. Before an optional
donation, a full Thursday–Monday stay is **€145** in a tent or on the floor, or **€210** for one
place in a double bed; both examples include the €50 Reservation Payment. Direct people to the
website for the calculator and current signup state rather than copying the external Form URL.

The venue and dates are confirmed.

taught before. The gathering is cost-shared: nobody profits, and participants contribute to the

## Field mapping and venue-specific constraints

- **DanceCal / BluesCal / FusionCal:** one submission can feed the family. Use `Exchange`; tick
  Blues and Fusion; do not submit the same edition three times.
- **SwingPlanIt:** use `Camp` and `Blues`. Its description field must not contain links, teacher
  names, cost figures or the venue address; put those in their dedicated fields.
- **fusion-dancing.eu:** use one route—Discord, GitHub or email—and record which one. Explain
  honestly that the programme is crowdsourced across blues and fusion.
- **Account-owned records:** update the existing edition when the service supports annual editions;
  do not create a duplicate simply because the old public page says 2026.
- **Fields labelled price/ticket:** use `cost-sharing` when free text is allowed. If the field
  requires a number, use the lowest complete Thursday–Monday example (€145) and explain the model
  in notes. Never imply that the €50 Reservation Payment is the whole event cost.
- **Teacher field:** `Community-led; workshops are proposed by participants.` Do not invent a
  lineup or promise named guests before they are confirmed.
- **Facebook event:** leave blank until an official event URL exists.

## Submission checklist for humans and agents

1. Open https://openblues.pl/ and confirm that signup is currently open. Stop if the public status
   says cancelled or the signup button is disabled.
2. Open the destination and search for `Open Blues`, the venue and the 2027 dates before creating
   anything. Update an existing record where possible.
3. Re-check the destination's current field rules. Use the canonical facts above; do not infer a
   city, price, teacher, social profile or capacity.
4. Use the shortest suitable copy. Do not add urgency, discounts, “limited places”, an application
   process or a signup deadline.
5. Use only public assets in this kit. Never upload participant or payment data.
6. Submit once. Capture the date, route, resulting status and public URL in `LISTINGS.md`.
7. Mark `SUBMITTED` only after the destination acknowledges the action. Mark `LIVE` only after
   opening the public 2027 listing and checking its dates, venue and website.
8. If login, moderation, CAPTCHA or ownership stops the run, mark `BLOCKED` with the exact next
   action. Do not work around access controls or create an organiser identity without approval.

## Drift rules

- `hugo.toml` is authoritative for event dates and the website signup state.
- `data/formprefill.json` and `contracts/signup-2027.json` are authoritative for current cost
  options and the Google Form contract.
- This launch kit owns reusable listing copy. `LISTINGS.md` owns external status. Keep those roles
  separate so copy changes do not rewrite history and status changes do not fork the facts.
- If any canonical fact changes, update this file and the public site in the same change, then
  revisit every `SUBMITTED` or `LIVE` listing that could now be stale.
